# 数据质量概览

数据质量不是一张问题列表，而是一套从规则定义、执行、结果聚合到问题定位的闭环。Yak Ops 的质量能力应当同时回答“哪里有问题”“问题有多严重”“问题是否在变好”以及“具体该去哪里处理”。

## 质控规则解决什么

规则或质控点用于描述一条可判断的质量要求。好的规则应该有清晰的检查对象、判断逻辑和结果口径，而不是把大量业务含义都藏在一个难以解释的表达式里。

## 运行结果怎么看

单条失败记录适合定位具体问题，但不能替代总体判断。质量总览更适合观察：

- 不同维度的问题分布；
- 规则通过率与异常量；
- 时间范围内的趋势变化；
- 哪些问题正在反复出现；
- 从汇总指标如何下钻到具体记录。

## 聚合口径必须一致

质量页面最容易出现的误解，通常不是图表本身，而是日期范围、分母、过滤条件和导出口径不一致。一个页面上的卡片、趋势、雷达或列表如果使用不同口径，即使每个 SQL 单独看都正确，最终也会给出冲突的结论。

因此质量文档会优先解释指标口径和下钻关系，再解释视觉组件。

## AI 质控属于规则能力的一部分

当检查对象是自然语言片段或文书内容时，可以由模型参与判断，但它仍然需要明确的输入片段、提示词、结果结构和失败边界。AI 不应成为绕过规则定义与可追踪性的黑盒入口。

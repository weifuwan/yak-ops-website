# 部署与运行概览

部署文档的目标不是提供一份只能在某台机器上成功一次的命令，而是先把运行边界讲清楚。具体版本、资源规格和中间件参数应当跟随正式发布基线维护。

## 上线前需要确认的边界

### 配置与密钥

数据库凭据、邮件凭据、第三方服务密钥等都应通过环境配置或密钥管理方式注入，不应提交到 Git。示例配置只描述键名和用途，不保存真实值。

### 数据库迁移

数据库结构变更需要可重复、可追踪。不同业务边界如果各自维护迁移历史，应使用独立 schema 或明确隔离的 Flyway history，避免多个模块争用同一迁移状态。

### 登录态与多实例

单实例环境可以使用本地内存能力完成开发验证；进入多实例部署后，Session、限流和需要跨节点共享的状态必须重新检查是否已经外置。

### 可观测性

上线不只需要“进程存活”。至少要能观察应用健康、关键接口失败、数据库连接和核心任务运行情况，才能区分入口故障、业务故障与下游依赖故障。

## 先验证最小链路

部署完成后，优先走一条短而完整的 smoke test：登录、访问受保护资源、执行一个最小业务动作、查看结果，再验证退出或会话失效。这样比一次性点击大量页面更容易定位基础设施问题。

# 数据开发概览

数据开发关注的是“任务如何被定义、执行和验证”。页面上的编辑器只是入口，更重要的是让任务定义、运行上下文、依赖关系和执行反馈保持一致。

## 一个开发任务需要回答什么

一个可维护的任务至少要能回答下面几个问题：

- 它处理什么数据；
- 它依赖哪些上游条件；
- 它在什么执行环境中运行；
- 成功和失败如何判断；
- 运行结果去哪里查看；
- 修改它可能影响哪些下游。

## 开发与运行要分开理解

“代码保存成功”和“任务运行成功”是两个不同状态。前者说明定义已经持久化，后者还取决于运行时环境、数据状态、依赖以及资源情况。

因此在阅读 Yak Ops 的数据开发页面时，可以把信息分成三层：

1. **定义层**：脚本、参数和任务元信息；
2. **执行层**：运行实例、调度上下文和资源状态；
3. **反馈层**：日志、结果、错误和下游影响。

## 和血缘、质量的关系

开发任务往往是血缘关系的重要来源，也可能是质量规则的检查对象。后续文档会尽量让“开发了什么”和“它影响了什么”能够互相跳转，而不是让用户在多个模块里重复寻找同一个对象。

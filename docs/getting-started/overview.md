# Yak Ops 概览

Yak Ops 面向数据工程与数据治理场景，把数据集成、数据开发、数据质量和数据血缘放在同一套工作流里理解。文档站本身需要登录后访问，文档源继续保存在 Git 中，便于和代码一起评审、回滚和演进。

## 你可以在这里了解什么

Yak Ops 的文档会围绕几条稳定主线展开：

- **数据怎么进来**：离线同步与实时同步承担不同的数据接入时效要求。
- **数据怎么加工**：数据开发关注任务定义、执行上下文和运行反馈。
- **数据是否可信**：数据质量把规则、执行结果、问题分布和趋势放在统一视角下观察。
- **数据从哪里来到哪里去**：数据血缘帮助理解上下游依赖和变更影响。

> 文档描述产品边界和使用思路。仍在快速变化的实现细节不会为了“看起来完整”而提前写死。

## 推荐阅读顺序

如果你第一次接触 Yak Ops，建议按下面的顺序阅读：

1. 先看「快速开始」，建立一条从接入到治理的完整心智模型。
2. 再进入「数据集成」和「数据开发」，理解数据进入平台后的生产链路。
3. 接着阅读「数据质量」与「数据血缘」，理解治理能力如何覆盖运行结果与上下游关系。
4. 准备部署时，再看「部署与运行」中的边界和检查项。

## 文档如何保持可信

这套文档不从数据库动态生成，也不在前端仓库里维护第二份副本。`docs/` 是唯一内容源，导航顺序由 `navigation.json` 明确声明，内容只会被打进后端制品并通过登录态保护的 API 下发。
